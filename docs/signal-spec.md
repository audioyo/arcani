# Signal Spec

This file is the only source of signal formulas (AD-19). The engine (`engine/`) and the Python reference (`reference/`) each implement it on their own; neither defines a formula of its own, and neither is ported from the other. A shape or stage not in this file does not exist.

Story 0.2 writes the core and sine sections. Story 1.2 writes the internal block size and the stub chain. Story 1.4 writes 24-bit rounding. Story 1.5 adds the theta reference oscillator to the stub chain. Later stories add envelope shapes, coupling, bursts, ramps and rate curves, loop seams, the limiter, the resampler, the loudness window, and the spectral component model.

**Conventions:**

- **binary64:** IEEE 754 double precision, round to nearest, ties to even, no fused multiply-add (`-ffp-contract=off`, AD-9). Every binary64 operation written here is one correctly rounded operation, evaluated in the order written.
- **Hex floats:** binary64 constants are written as C99 hex float literals, so both sides start from the same bits.
- **Exact:** "exact" means integer or rational arithmetic with no rounding.
- **Worked vectors:** every vector table below is generated by `tools/signal_spec_vectors.py` from exact arithmetic (`fractions`) and 60-digit decimal arithmetic (`decimal`), never from the engine, and lives once in `tests/data/signal_spec_vectors.json`. A test checks that each table here equals that file. The engine test (`tests/cpp/`) and the Python ideal test (`tests/python/test_signal_spec_core.py`) each pass every vector on their own. To change a vector, change the generator, run it, and paste its `--tables` output here.

## Core

### Phase accumulator

Every oscillator keeps its phase in an unsigned 64-bit integer. One cycle is 2^64 phase units, so phase `p` stands for the fraction `p / 2^64` of a cycle.

```
phase[0]   = start phase (0 unless a later section says otherwise)
phase[n+1] = (phase[n] + inc) mod 2^64
```

The addition wraps modulo 2^64 (unsigned overflow). Phase is never stored in floating point. After `n` samples the phase is exactly `(phase[0] + n * inc) mod 2^64`, so phase error never accumulates beyond the error in `inc` itself.

### Phase increment rule

For a frequency `f_hz` (a binary64 value, in Hz) at sample rate `fs` (a positive integer, 44100 or 48000, held exactly in binary64):

```
q   = (f_hz * 0x1p64) / fs      binary64: the multiply is exact, the division rounds once
inc = q rounded to the nearest integer, ties to even, as an unsigned 64-bit integer
```

Domain: `0 <= f_hz < fs / 2`. Any other `f_hz`, NaN and both infinities included, gives `inc = 0`. The rule never fails or throws. Negative zero is in the domain and gives `inc = 0`.

An exact tie (`q` exactly k + 1/2) can happen whenever `q` is below 2^52, that is for `f_hz` below about `fs / 4096` (about 10.8 Hz at 44.1 kHz and 11.7 Hz at 48 kHz), which includes the theta rate band; at or above 2^52 every binary64 `q` is already an integer. The tie vectors below exercise it, both at tiny frequencies and in the 1 to 6 Hz band. `inc` is at most 2^63, so it always fits.

**Frequency error.** The frequency the accumulator plays is `f_q = inc * fs / 2^64`. Two errors make up `|f_q - f_hz|`: the division rounding (at most half a unit in the last place of `q`) and the integer rounding (at most 1/2). For `f_hz` up to 1030 Hz, `q` is below 2^59, so `|inc - f_hz * 2^64 / fs|` is at most 32.5 and `|f_q - f_hz|` is at most `32.5 * fs / 2^64`, about 8.5e-14 Hz at 48 kHz.

**Drift.** Over a session of `T` seconds the timing error of a signal at `f_hz > 0` is `|f_q - f_hz| * T / f_hz` seconds. At 0 Hz, `inc = 0` and there is no drift.

### Seconds-to-samples rule

Every time value in a recipe or in this spec is in seconds and converts to a sample count by one rule (AD-10):

```
x = t_s * fs                    binary64, one rounding
n = x rounded to the nearest integer, ties to even, as an unsigned 64-bit integer
```

Domain: `t_s >= 0` and finite, with `x < 2^64`. Any other `t_s` (negative, NaN, infinite, or one whose product reaches 2^64) gives `n = 0`.

## Sine

### Ideal sine

The ideal sine of a phase is

```
y = sin(2 * pi * phase / 2^64)
```

evaluated exactly (in real numbers). Sample `n` of an unmodulated sine oscillator is the sine of `phase[n]`, read before the increment is added. The Python reference renders the ideal sine, never the engine approximation (design log 2026-10-28 (o)).

### Engine sine

The engine owns its sine (AD-9: no libm). For a phase `p`:

1. **Fold, exact integer steps.** Read `p` as a signed 64-bit two's-complement integer `s`, in `[-2^63, 2^63)`, so `s / 2^64` is the signed fraction of a cycle. Fold into `[-2^62, 2^62]` with `sin(pi - x) = sin(x)`:
   - if `s > 2^62`: `s = 2^63 - s`
   - if `s < -2^62`: `s = -2^63 - s`
   - otherwise `s` is unchanged.

   Each step is exact in 64-bit integer arithmetic (compute it in unsigned arithmetic modulo 2^64 and read the result as signed).
2. **Convert once.** `x = double(s) * 0x1.921fb54442d18p-62`. `double(s)` is the one int64-to-binary64 conversion (round to nearest, ties to even). The constant is the binary64 nearest to pi, scaled by 2^-63 (exact; equivalently pi/2 times 2^-62), so it is the binary64 nearest to `2 * pi / 2^64`; the multiply is one rounding. `x` lies in `[-pi/2, pi/2]`.
3. **Odd Taylor polynomial to x^11, fixed Horner order.** With the coefficients below:

   ```
   z = x * x
   r = C11
   r = r * z + C9
   r = r * z + C7
   r = r * z + C5
   r = r * z + C3
   r = r * z + C1
   y = r * x
   ```

   Each `*` and `+` is one binary64 operation (no fused multiply-add). `C1` is exactly 1.

The engine sine returns `y` as binary64. Converting it to float32 for output is a separate step, round to nearest, ties to even.

**Coefficients.** `Ck` is the binary64 nearest to `±1/k!` (sign alternating, `+` for k = 1). They are exact-derivable, so no fitted constant needs a source.

### Error bound

```
20 * log10( max over the test phases of |engine sine(p) - ideal sine(p)| ) <= -120 dBFS
```

Full scale is 1.0. Source: design log 2026-10-28 (o) (engineering default; margin under the -100 dBFS reference match). Truncation error of the polynomial on `[-pi/2, pi/2]` is at most `(pi/2)^13 / 13!`, about 5.7e-8 (-145 dBFS), so the bound holds with about 25 dB to spare before rounding.

**Test resolution.** The test phases are the 2^24 evenly spaced phases `k * 2^40` for `k = 0 .. 2^24 - 1` (one full cycle), plus each quadrant edge `0, 2^62, 2^63, 3 * 2^62` and its neighbours `edge - 1` and `edge + 1`, modulo 2^64.

## Internal block size

The engine renders in internal blocks of 64 frames. A frame is one sample per channel (left, then right). The block size is a fixed engine constant, not a recipe parameter: it never shapes the signal. Source: engineering default, design log 2026-11-04 (gg).

```
block_frames = 64
block(k)     = k div 64        frame k lies in this block
offset(k)    = k mod 64        at this offset inside it
```

Every sample is a pure function of the plan and its sample index `n` (AD-10). A host request of any length is served from the internal blocks, so neither the block size nor the host's request size changes a sample. Story 1.6 proves block-size invariance.

**Seek.** Seek to frame `k` sets every oscillator phase to exactly `(phase[0] + k * inc) mod 2^64`, the same value sample-by-sample stepping reaches, and the next rendered sample is sample `k`. Seek reads no earlier output, so it is pure. Seeking to any `k`, including one past the session end, is allowed.

## Stub chain

The fixed stage list of Story 1.2, before any real layer exists. Story 1.5 routes the sine through the theta reference stub as an unmodulated carrier; Epic 2 replaces the theta reference and gamma PAC stubs with the real layers, and Epic 4 replaces the stored gain and the limiter stub.

**Stage order.** Theta reference, gamma PAC layer, stereo bus, binaural join, master chain (per-channel gain, then a stereo-linked limiter). The order is fixed and is not a recipe field. Every stage writes channel `c` only from channel `c` of its inputs. The limiter alone reads both channels, and only to derive one linked gain that it applies to each channel separately. No stage reads one channel to write the other.

**Session length.** `N = seconds_to_samples(length_s, fs)` frames (Core, seconds-to-samples rule). For `n >= N` every tap and the output are exactly `+0.0` in both channels.

**Theta reference oscillator (Story 1.5).** With a `theta_reference` field, one unmodulated sine at the theta carrier, the same value in both channels:

```
f_T   = theta_reference.carrier_hz
inc_T = phase increment rule (f_T, fs)
phase_T[0] = 0,  phase_T[n] = n * inc_T mod 2^64
a_T   = 1.0                                 unit amplitude
```

A recipe without a `theta_reference` field has `a_T = 0.0` and `inc_T = 0`. The stub has no amplitude modulation, envelope, or level of its own: the theta-rate modulation and the envelopes arrive in Epic 2, and the stored gain in Epic 4. For the fixture `stub-chain-1s-beat-6.json` it is a 300 Hz unmodulated sine in each channel; `stub-chain-1s-beat-0.json` has no `theta_reference` field.

**Binaural oscillators.** One unmodulated sine per ear:

```
f_L   = carrier_left_hz
f_R   = carrier_left_hz + beat_rate_hz      binary64, one rounding (range row binaural-carrier-right)
inc_c = phase increment rule (f_c, fs)      c = L or R
phase_c[0] = 0,  phase_c[n] = n * inc_c mod 2^64
a_c   = 1.0                                 unit amplitude
```

For the fixture `stub-chain-1s-beat-6.json` that is a 400 Hz unmodulated sine in the left ear and a 406 Hz unmodulated sine in the right ear, a 6 Hz binaural beat; for `stub-chain-1s-beat-0.json` it is a 400 Hz unmodulated sine in each ear. A recipe without a `binaural` field has `a_L = a_R = 0.0` and `inc_L = inc_R = 0`.

**Muted ear.** The compile option `mute_binaural_ear` (none, left, or right) is an offline measurement control for the isolation test (FR-4), stored in the plan; it is not a recipe field. For the muted ear `c`, the plan holds `inc_c = 0` and `a_c = 0.0`, so the render path has no test branch and that ear's binaural oscillator outputs `0.0 * sine(0) = +0.0`. Muting affects only the binaural oscillator: the theta reference is unchanged, so the muted channel's `join`, `master`, and `out` equal its `theta` bit for bit.

**Per sample.** For `0 <= n < N` and each channel `c`, in this order, each line one binary64 operation (Conventions):

```
theta[c][n]  = a_T * sine(phase_T[n])       theta reference stub: the same value in both channels (Sine, engine sine)
gamma[c][n]  = 0.0                          gamma PAC stub
bus[c][n]    = theta[c][n] + gamma[c][n]    stereo bus: adds the layers within channel c
bin[c][n]    = a_c * sine(phase_c[n])       binaural oscillator of ear c (Sine, engine sine)
join[c][n]   = bus[c][n] + bin[c][n]        binaural join: ear c is added to channel c only
master[c][n] = join[c][n] * g_c             per-channel gain, g_L = g_R = 1.0 (stored gain is Epic 4)
out[c][n]    = master[c][n]                 stereo-linked limiter stub: identity, zero gain reduction
```

`y * 1.0 = y` exactly for every binary64 `y`, and `y + +0.0 = y` and `+0.0 + y = y` exactly for every binary64 `y` other than `-0.0` (where the sum is `+0.0`). Neither oscillator ever produces `-0.0`: the engine sine (Sine, Engine sine) returns zero only for a folded `s = 0`, where `x = +0.0`, `r = C1 = 1` and `y = 1 * +0.0 = +0.0`, and is otherwise nonzero with the sign of `s`, since `r` stays positive on `[-pi/2, pi/2]`; an absent theta reference, a muted ear, or an absent ear is `0.0 * sine(0) = +0.0`. So `bus = theta` bit for bit. `join = bus + bin` is one rounding; it is exact, and equals the other operand, when `theta` or `bin` is `+0.0` (no `theta_reference` field, or a muted or absent ear). `master` and `out` equal `join` bit for bit.

**Level.** Both stub oscillators run at unit amplitude, so a recipe with a theta reference and a binaural layer peaks near 2.0. `stub-chain-1s-beat-6.json` (300 Hz theta, 400 and 406 Hz binaural) does, and its 24-bit WAV clips by the 24-bit rounding rule (24-bit rounding). It is a test fixture, not for listening; real levels arrive in Epic 2 and Epic 4.

**Output and taps.** The render output is `out`, interleaved stereo binary64 (left, then right, per frame). Five optional taps, each interleaved stereo binary64 over the same frames: theta reference (`theta`), gamma PAC (`gamma`), stereo bus (`bus`), binaural join (`join`, the engine output point of the isolation row `binaural-isolation-engine`), and master (`out`, the point of row `binaural-isolation-master`).

**Seek.** Seek to frame `k` sets `phase_T` to `k * inc_T mod 2^64`, the same rule as the binaural phases (Internal block size, Seek).

## 24-bit rounding

The command-line renderer (Story 1.4) writes the render output (Stub chain, Output and taps) as 24-bit PCM. Each binary64 output sample `s` becomes one signed 24-bit integer `v` by this rule. There is no dither and no other shaping.

```
if s is NaN:            v = 0                      any sign or payload
x = s * 0x1p23          binary64, exact (see below)
if x >= 8388607:        v = 8388607                +1.0, everything above full scale, +inf
else if x <= -8388608:  v = -8388608               -1.0, everything below, -inf
else:                   v = x rounded to the nearest integer, ties to even
```

`v` is written as 3 bytes, little-endian two's complement: the bytes of `v mod 2^24`, least significant first. Samples are written in render order, left then right per frame.

**Exactness.** Scaling by 2^23 is exact for every finite `s`: it only changes the exponent, a subnormal `s` moves toward the normal range and loses no bits, and a product too large for binary64 becomes an infinity of the same sign, which the clamp treats the same as the exact value. The comparisons are exact. In the last branch `|x| < 2^23`, so `x` and its fractional part `x - floor(x)` are exact binary64 values, and the tie test compares that part with exactly 1/2. No step depends on the host rounding mode or denormal mode: a subnormal `s` gives `v = 0` whether or not the host flushes it.

**Range.** The 24-bit range is asymmetric: +1.0 maps to 8388607 (2^23 - 1), and -1.0 to -8388608 (-2^23). Signed zeros and every `|x| < 1/2` give 0; `|x|` exactly 1/2 also gives 0 (ties to even).
